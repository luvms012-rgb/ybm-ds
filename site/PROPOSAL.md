## 1. 설치 방법 (2순위, 개발자용)

지금 사이트에 있는 설치 방법은 모두 바로 쓸 수 있는 것이다.

| 순위 | 방법 | 지금 | 누가 |
|---|---|---|---|
| 1 | CSS 두 줄(`<link>` + `<script>`) | 됨 | 모두 |
| 1-1 | 공개 CDN 주소에 커밋 번호로 버전 고정 | 됨 | 개발자 |
| 1-2 | 저장소 내려받아 `dist/` 복사 | 됨 | 개발자, 사내 서버 |
| 2 | **npm 패키지** | 안 됨 - 제안 | 개발자 |
| 3 | npx 로 컴포넌트 코드 복사 | 안 됨 - 권장하지 않음 | - |

### npm, npx 가 뭔가요
- **npm** 은 개발자들이 쓰는 "부품 가게"다. `npm install 이름` 한 줄로 프로젝트에 라이브러리를 받고, 버전 번호로 관리한다. React, Vue, Next.js 같은 요즘 프로젝트는 거의 모두 이 방식으로 CSS 와 JS 를 들여온다.
- **npx** 는 npm 에 올라온 프로그램을 설치 없이 한 번 실행하는 명령이다. 요즘 유행하는 "컴포넌트 코드를 내 프로젝트에 복사해 넣는" 방식(`npx 도구 add button`)이 이것이다. 이 방식은 React 컴포넌트처럼 **코드 파일**을 나눠 주는 DS 에 맞고, yds 처럼 **CSS 한 벌**로 된 DS 에는 맞지 않는다(복사본이 생기면 DS 를 고쳐도 반영되지 않는다).

### 권장안: npm 패키지 하나
```
npm install @ybm/ds            ← 패키지 이름은 정해야 한다
```
```js
import '@ybm/ds/dist/ybm-ds.css';   // 빌드 도구(Vite, Next.js 등)가 알아서 묶는다
import '@ybm/ds/dist/ybm-ds.js';
```
- 필요한 것: `package.json` 1개, 버전 번호 규칙(아래 3-1), npm 계정과 배포 1회. 코드는 지금 그대로.
- 얻는 것: 개발자는 익숙한 방식으로 설치하고, 버전을 올릴 때만 바뀌어 안전하다. 공개 CDN 이 npm 패키지를 자동으로 따라 올라가서 `https://cdn.jsdelivr.net/npm/@ybm/ds@1.0.0/dist/ybm-ds.css` 같은 버전 주소도 생긴다.
- 사내 전용이면 공개 npm 대신 사내 저장소(GitHub Packages 등)에 올릴 수 있다. 공개 범위(3-6)와 함께 정한다.

## 3. 정책과 가이드 (DS 에 아직 없는 것)

### 3-1. 버전과 변경 관리 ★
- 버전 번호 규칙: 큰 번호(클래스 이름이 바뀌어 화면이 깨질 수 있음) / 중간 번호(새 컴포넌트) / 작은 번호(값 조정, 버그).
- 변경 기록 페이지: 지금은 README 표에만 있다. 사이트에 "새 소식" 으로 보여 주면 쓰는 사람이 무엇이 바뀌었는지 안다.
- 없어지는 클래스는 바로 지우지 않고 한 버전 동안 남겨 둔다.

### 3-2. 한글 타이포그래피 토큰 ★
사이트와 템플릿은 국내 주요 서비스의 글자 위계를 따라 아래 규칙을 쓰고 있지만, **DS 토큰에는 자간과 긴 글 줄 높이가 없다.**
| 제안 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--ds-letter-spacing-tight` | -0.02em | 20px 이상 제목 |
| `--ds-letter-spacing-snug` | -0.01em | 15~19px 본문과 소제목 |
| `--ds-letter-spacing-normal` | 0 | 14px 이하 |
| `--ds-line-height-reading` | 1.7 | 긴 글 본문 |
- 함께: 글자 스타일(제목 1~4, 본문, 라벨, 보조)을 역할 이름으로 정리할지 다시 검토. 지금은 번호(t01~t17)만 있어 사람마다 다른 번호를 고른다.

### 3-3. 페이지 레이아웃 규칙 ★
- 템플릿마다 본문 최대 폭과 사이드바 폭을 따로 정했다(640, 1200, 240 등). 페이지 폭, 사이드바 폭, 열 수(모바일 4 / 태블릿 8 / PC 12 등)를 토큰이나 레이아웃 클래스로 정하면 화면끼리 맞춰진다.

### 3-4. 접근성 기준
- 목표 수준(예: 웹 접근성 지침 2.1 AA), 글자와 배경 대비, 키보드 이동, 포커스 표시, 화면 읽기 프로그램용 라벨 규칙.
- 컴포넌트 페이지에 "접근성" 칸을 두고 컴포넌트마다 지켜야 할 속성(aria-*)을 정리.

### 3-5. 글쓰기 가이드
- 말투(~해요), 버튼 라벨(동사로 끝내기, 2~6자), 오류 문구(원인 + 해결), 빈 화면 문구(상황 + 다음 행동).
- 지금은 Figma 설명과 README 에 흩어져 있다. 한 페이지로 모으면 기획자가 바로 쓴다.

### 3-6. 사용 범위와 공개 범위
- 적용 대상: 어떤 서비스가 반드시 써야 하는지, 예외는 어떻게 받는지.
- 지원 브라우저: DS 는 CSS 레이어, `:has()`, `aspect-ratio` 를 쓴다. 최신 Chrome, Safari, Edge, Firefox 기준이고 오래된 브라우저는 따로 정해야 한다.
- 공개 범위: 지금 저장소와 사이트는 누구나 볼 수 있다. 회사 정책 확인 필요.
- 브랜드: 로고 사용 규칙, 서비스별 브랜드 색 교체 방법(README 에 기술 방법만 있음).

### 3-7. 기여 방법
- 새 컴포넌트나 변경 요청 절차, Figma 와 CSS 를 같은 날 함께 고치는 규칙, 검토자.

## 7. 템플릿 추가와 고도화 검토 (2026-10-31 집, 사용자 요청)

사내 UI Patterns 모음(웹 26,712장, 분류 59개, 큰 묶음 7개)을 기준으로 우리 템플릿 26종을 대조했다. 사용자가 짚어 준 서비스 3곳(금융 조회형, 보험 다이렉트형, 소상공인 관리자형)의 화면 구성도 함께 봤다. 템플릿은 범용이므로 서비스 이름이 아니라 화면 유형으로 적는다. 자세한 출처는 로컬 REFERENCE-ANALYSIS.md 에만 있다.

### 7-1. 지금 있는 것과 빈 곳

## 9. 템플릿 62종을 다듬으며 부족했던 DS (2026-11-02 회사, 사용자 "ds가 부족하면 제안해줘")

템플릿 안에서 `tp-*` 로 직접 만들어 쓴 것들이다. 여러 템플릿에서 되풀이되므로 DS 부품으로 올리면 서비스에서도 그대로 쓸 수 있다. 위에서부터 급한 순서.

- Select 의 `small` 크기가 없어 표 머리와 도구 줄에서는 medium(40)을 썼다. 32 높이 small 이 있으면 표 도구 줄이 더 촘촘해진다.

### 10-2. 제안 구성 (위에서 아래 순서)

1. **머리**: 제목 Get Started 아래 의도 한 문장. 예: "yds는 디자이너, 개발자, AI가 같은 이름으로 같은 화면을 만들게 돕는 디자인 시스템입니다." 그 아래 큰 인터랙션 영역(10-3).
2. **yds가 지키는 것** (카드 4개, 한 줄씩)
   - 쉽게: 보자마자 복사해 쓸 수 있게, 규칙과 선택지는 적게.
   - 하는 일로 고르기: 생김새가 아니라 하는 일(고르기, 동작, 이동, 알림)로 부품을 고른다.
   - 하나의 이름: Figma 변수, CSS 토큰, AI 규칙 파일이 같은 이름을 쓴다.
   - 어디서나: 특정 서비스에 묶이지 않고 다크 모드와 반응형을 처음부터 갖춘다.
3. **시스템 이해하기** (B 구성): Foundations(색, 글자, 간격), Components 71종, Templates 67종 카드. 카드마다 작은 미리보기와 개수.
4. **나에게 맞는 시작** (C, E 구성): 세 입구
   - 디자이너: Figma 라이브러리 열기, AI 대화창에 llms-full.txt 첨부
   - 개발자: head 에 두 줄, AGENTS.md 두기, yds-check.mjs
   - AI로 만드는 사람(기획, 운영): 요청 글 4개 복사
   각 입구를 누르면 아래 해당 절로 내려간다.
5. **바로 시작하기**: 지금의 "AI로 시작하기"와 "직접 시작하기"를 탭 하나(AI로 / 직접)로 묶어 길이를 반으로.

### 10-3. 첫 화면 인터랙션

레퍼런스에서 본 방식:
- A: 그 시스템 부품으로 만든 실제 카드(상품, 채팅 입력, 포인트 막대)가 제목 둘레에 떠 있고, 점 5개로 테마가 바뀌며 같은 카드가 다른 옷을 입는다. "마음대로 바꿀 수 있다"는 의도를 그림으로 보여 준다.
- B: 브랜드 마크의 선을 크게 그린 어두운 그래픽.
- C: 사진과 화면 모음이 움직이고, 왼쪽 아래 "애니메이션 멈춤" 버튼이 있다. 움직임 줄이기 설정을 따른다.
- D: 유리 질감의 실제 UI 조각(스위치, 슬라이더, 버튼)이 입체로 떠 있다.
- E: 제목 "Let the ( ) flow" 의 가운데 낱말이 바뀌며 돌고, 3D 도형이 있다.

yds 의도에 맞춘 후보:

| 후보 | 무엇을 보여 주나 | 전하는 의도 | 비용 |
|---|---|---|---|
| **A. 하나의 이름** (권장) | 실제 yds 부품으로 만든 작은 화면(주문 카드, 입력칸, 버튼, 배지). 부품에 마우스를 올리거나 누르면 이름표(예: Button / neutralSolid)가 뜨고, 옆 작은 탭 디자인 / 코드 / AI 가 같은 이름으로 바뀐다 | Figma, 코드, AI 가 같은 이름. 부품은 하는 일로 고른다 | 중간. 실제 DS CSS 만 쓰면 된다 |
| B. 같은 화면, 다른 옷 | 같은 화면이 기본 → 다크 → 브랜드 색 바꾸기 순으로 바뀐다. 점 페이저와 멈춤 버튼 | 토큰만 쓰면 다크와 브랜드가 따라온다 | 낮음. data-theme 와 브랜드 토큰만 바꾼다 |
| C. 요청 글이 화면으로 | 입력창에 "주문 내역 화면 만들어 줘"가 쳐지고, yds 부품이 하나씩 쌓여 화면이 완성된다 | AI 가 읽고 바로 만든다 | 중간. 재생 순서만 짠다 |
| D. 브랜드 마크 | YBM 마크 선이 그려지는 그래픽 | 브랜드 인상 | 낮음. 정보는 적다 |

권장: 첫 화면은 **A 를 바탕으로 B 를 더한 것**. 부품 이름표(A)로 "하나의 이름"을 보여 주고, 화면 아래 점 3개로 기본 / 다크 / 브랜드 색(B)을 바꾼다. C 는 5번 "바로 시작하기"의 AI 탭 옆 작은 재생 그림으로 쓴다.

인터랙션 규칙:
- 움직임은 DS 모션 토큰(duration, easing)만 쓴다.
- 저절로 바뀌는 것은 멈춤 버튼을 둔다(5초 넘게 움직이는 것). `prefers-reduced-motion` 이면 처음부터 멈춘 첫 장면.
- 마우스 올리기는 키보드 포커스와 터치(누르기)로도 똑같이 된다. 이름표는 Tooltip 규칙.
- 무거운 라이브러리 없이 DS CSS 와 짧은 스크립트로. 그림 파일 대신 실제 부품이라 다크 모드와 글자 크기 변화를 그대로 따른다.
